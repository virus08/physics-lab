## 1. ผู้พัฒนาและการแบ่งงานตามโมเดล

งานพัฒนาทำโดย Claude ทั้งหมด แบ่งตามความเสี่ยงของงานได้ดังนี้

| งาน | ความเสี่ยงถ้าผิด | โมเดลที่เหมาะ |
|---|---|---|
| ไลบรารีร่วม physlab.js (เอนจิน การวาด กราฟ) | ผิดแล้วกระทบทั้ง 76 ชุด | โมเดลใหญ่ (Opus หรือ Fable) เขียนและตรวจ |
| ฟังก์ชันคำตอบเชิงวิเคราะห์และชุดทดสอบความแม่น | ถ้าเกณฑ์ผิด การทดสอบจะผ่านทั้งที่ฟิสิกส์ผิด | โมเดลใหญ่เขียน หรือ Sonnet เขียนแล้วโมเดลใหญ่ตรวจ |
| แบบจำลองรายชุดจากแม่แบบตามการ์ด | ผิดเฉพาะชุดนั้น และชุดทดสอบจับได้ | Sonnet ทำได้ เพราะเป็นงานทำซ้ำตามสเปกชัด |
| เนื้อหาในแผง (summary, tryIt, reference) | ข้อความผิด | Sonnet คัดลอกจากไฟล์สรุป ไม่แต่งเอง |
| ตรวจรับรายบท | | โมเดลใหญ่ทบทวนผลทดสอบและภาพหน้าจอก่อนส่งเจ้าของ |

กติกาเมื่อใช้ Sonnet: ให้อ่าน 03-sdd.md หัวข้อ 3, 4 และ 6 กับการ์ดของชุดนั้นก่อน ห้ามแก้ไลบรารีร่วม ถ้าพบว่าไลบรารีขาดความสามารถ ให้บันทึกเป็นประเด็นแล้วหยุด ไม่แก้เอง


## 3. เพิ่มแบบจำลองใหม่ทีละขั้น

1. **เปิดการ์ดออกแบบ** ของชุดนั้นบนแคนวาส จดสิ่งที่ปรับได้ สิ่งที่เห็น กราฟ และชุดค่าสำเร็จรูป
2. **เขียนตารางสเปก** แบบเดียวกับ 03-sdd.md หัวข้อ 6.3 ลงในส่วนหัวคอมเมนต์ของไฟล์ (params, presets, world, step, draw, readouts, formulas, graphs, analytic, เกณฑ์)
3. **คัดลอกแม่แบบ** `sims/_template.html` เป็น `sims/chNN-sM-<slug>.html` ตามรูปแบบ FI-02
4. **เติม config** ตามลำดับ: params และ presets ก่อน แล้ว init กับ step จากสูตรในไฟล์เนื้อหา แล้วค่อย draw, readouts, formulas, graphs
5. **ใส่เนื้อหา** คัดลอกคำอธิบายเรื่องจาก `physics-summary-20-chapters-easy.md` ลง `content.summary` เขียน `tryIt` 2 ข้อ และถ้าชุดนั้นมีเรื่องอ้างอิง ใส่ตารางใน `content.reference`
6. **เขียนฟังก์ชันเชิงวิเคราะห์** ใน `window.PhysLabSims['SM.N'].analytic` สำหรับใช้ทดสอบ
7. **เพิ่มรายการใน catalog.json** สถานะ `draft`
8. **เขียนทดสอบ** ใน `tests/physics.test.mjs` อย่างน้อย 1 กรณีเทียบ analytic ตามเกณฑ์ของชุด
9. **รัน** `npm run lab:test` ต้องผ่านทั้งหมด
10. **เปิดบนมือถือ** (หรือย่อหน้าต่างเป็น 390 px) ตรวจว่าอ่านค่าได้ ปุ่มกดได้ ภาพพอดีกรอบ
11. **ส่งตรวจรับ** พร้อมภาพหน้าจอเดสก์ท็อปและมือถือ และผลทดสอบตามจริง ถ้ามีข้อใดไม่ผ่านให้ระบุ
12. เมื่อผ่าน เปลี่ยนสถานะเป็น `ready` และบันทึกใน 07-changelog.md

## 4. มาตรฐานโค้ด

| หัวข้อ | กติกา |
|---|---|
| ภาษา | JavaScript ES2022 ไม่ใช้ TypeScript ไม่ใช้ import/export ในหน้าแบบจำลอง |
| ชื่อตัวแปร | ใช้สัญลักษณ์เดียวกับสูตร: `u`, `v`, `a`, `theta`, `omega`, `k`, `m`, `g` และหน่วย SI เสมอ (NFR-M5) |
| ฟิสิกส์ | `init` และ `step` เป็นฟังก์ชันบริสุทธิ์ ไม่แตะ DOM ไม่อ่านเวลาเครื่อง ไม่สุ่มเอง (ใช้ `PhysLab.rng`) |
| สูตร | ต้องตรงกับไฟล์เนื้อหาที่สกัดไว้ ถ้าเพิ่มสูตรนอกเหนือ (แรงต้าน ความหน่วง) ให้ปิดเป็นค่าเริ่มต้นและติดป้าย "ส่วนขยาย" |
| ข้อความ | ภาษาไทย ห้ามอักขระ Unicode แบบซ้อน (ลูกศรบนตัวอักษร ขีดบน) ใช้ตัวยกตัวห้อยอักขระเดี่ยวได้ (², ₁, θ, ω) |
| สี | ใช้ `Draw.color.*` เท่านั้น ห้ามใส่รหัสสีในไฟล์แบบจำลอง |
| ภาพ | ห้ามใช้ `<img>` หรือไฟล์ภาพ ทุกอย่างวาดด้วย canvas หรือ SVG ในโค้ด |
| เครือข่าย | ห้าม fetch หรือโหลดสคริปต์ภายนอก |
| ขนาด | ไฟล์แบบจำลองไม่เกิน 300 KB |
| ความคิดเห็นในโค้ด | ส่วนหัวตาม NFR-M3 และคอมเมนต์อธิบายสูตรตรงจุดที่ใช้ |

## 7. ปัญหาที่พบบ่อยระหว่างพัฒนา

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ภาพไม่ขยับ | `step` คืน state เดิม หรือ `running` ไม่ถูกตั้ง | ตรวจว่า step คืนอ็อบเจกต์ใหม่หรือแก้ค่าแล้วคืน และกดเล่น |
| ค่าอ่านเป็น NaN | หารด้วยศูนย์เมื่อพารามิเตอร์ขอบช่วง | ตั้ง min ให้ไม่เป็นศูนย์ หรือจัดการกรณีพิเศษใน step |
| ภาพหลุดกรอบ | world ตั้งค่าคงที่แต่ค่าพารามิเตอร์ใหญ่ | ใช้ `'auto'` หรือ `fit: 'follow'` |
| ทดสอบ determinism ไม่ผ่าน | ใช้ `Math.random` หรือ `Date.now` ใน step | เปลี่ยนเป็น `PhysLab.rng(seed)` |
| เสียงไม่ออกบน iPhone | สร้าง AudioContext ก่อนผู้ใช้แตะ | สร้างหลังกดปุ่มเล่นครั้งแรก |
| เปิด file:// แล้ว catalog ไม่โหลด | เบราว์เซอร์บล็อก fetch จาก file:// | index.html ใช้สำเนา catalog ที่ฝังไว้ (SDD หัวข้อ 8) |

## 8. ส่วนเพิ่มของ API ที่ใช้จริงในชุด 1.0.0

- `world` ควรมีอัตราส่วนกว้าง : สูง ใกล้ 1.9 : 1 เพราะพื้นที่วาดรักษาอัตราส่วนเสมอ (กรอบที่สูงมากจะถูกย่อจนเล็ก ดู KI-7) ชุดที่ใช้พิกัดกลาง ๆ มักตั้ง `{ xMin: 0, xMax: 10, yMin: 0, yMax: 5.2 }`
- `static: true` สำหรับแบบจำลองที่ไม่มีเวลา (เช่น เลนส์ ตัวเก็บประจุ) ระบบจะซ่อนปุ่มเล่นและวาดใหม่ทันทีเมื่อปรับค่า
- `dragHandles(state, params, D)` คืนรายการจุดลาก `{ param, x, y, r, map(wx, wy) }` โดย `map` คืนตัวเลขค่าเดียว หรือคืนออบเจ็กต์ `{ px: ..., py: ... }` เพื่อตั้งหลายพารามิเตอร์พร้อมกัน (ใช้ใน S9.4 S11.2 S13.1 S13.3 S18.4)
- `onParam(key, value, params, state)` ถูกเรียกทุกครั้งที่ค่าพารามิเตอร์เปลี่ยน ใช้ปรับเสียงหรือสถานะที่ต้องตามค่าใหม่ทันที (บท 12)
- `audio: true` เพิ่มปุ่ม "ปิดเสียง" ส่วนปุ่ม "ฟังเสียง" สร้างเองใน `setup(api)` ด้วย `api.addButton(label, fn)` แล้วใช้ `PhysLab.Audio.tone(id, { freq, gain })`, `Audio.set(id, { freq, gain })`, `Audio.stop(id)`
- `D.ctx` ใช้วาดรูปที่ไลบรารีไม่มี (เช่น วงรีด้วย `ctx.ellipse`) และตั้ง `ctx.globalAlpha` หรือ `globalCompositeOperation` ก่อนเรียก `D.*` ได้ โดยครอบด้วย `ctx.save()`/`ctx.restore()`
- แบบจำลองที่คำนวณสนามทั้งผืน (S9.3 S9.4) วาดลง canvas นอกจอขนาดเล็ก (ประมาณ 100×80) แล้ว `drawImage` ขยาย เพื่อให้ได้ 60 เฟรมต่อวินาที
