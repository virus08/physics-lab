## 1. ภาพรวมโครงการ

### 1.1 ชื่อและที่ตั้ง

Physics Lab อยู่ในโฟลเดอร์ `lab/` ของโปรเจกต์ cinematic-studio แต่เป็นระบบอิสระ ไม่เกี่ยวข้องกับระบบผลิตวิดีโอที่อยู่ในโปรเจกต์เดียวกัน ทั้งสองระบบใช้เสริมกันได้โดยไม่ต้องเชื่อมโค้ด

### 1.2 เป้าหมาย

ให้นักเรียน ม.ปลาย มีแบบจำลองที่ปรับค่าแล้วเห็นผลทันที สำหรับทุกเรื่องในบทเรียนฟิสิกส์ 20 บท เพื่อใช้ทำความเข้าใจบทเรียนด้วยตัวเอง ควบคู่กับการสอนในห้องเรียนหรือวิดีโอ

### 1.3 ผลลัพธ์ที่ส่งมอบ

| ลำดับ | ผลลัพธ์ | รูปแบบ |
|---|---|---|
| 1 | ชุดเอกสาร SDLC ครบ 7 ขั้น | ไฟล์ Markdown ใน `lab/docs/` |
| 2 | แบบหน้าจอ: แคตตาล็อก หน้าแบบจำลอง และการ์ดออกแบบ 76 ชุด | แคนวาสออกแบบ (ลิงก์ใน README) |
| 3 | ไลบรารีร่วม `physlab.js` และแม่แบบแบบจำลอง | โค้ดใน `lab/lib/` และ `lab/sims/_template.html` |
| 4 | แบบจำลอง 76 ชุด ครอบคลุม 195 เรื่อง | ไฟล์ HTML ใน `lab/sims/` ชุดละไฟล์ |
| 5 | แคตตาล็อกและไฟล์ข้อมูลรายการ | `lab/index.html`, `lab/data/catalog.json` |
| 6 | ชุดทดสอบอัตโนมัติ | `lab/tests/` |

### 1.4 สิ่งที่ไม่ทำในโครงการนี้

ระบบหลังบ้าน บัญชีผู้ใช้ แบบฝึกหัดตรวจคำตอบ และการเชื่อมต่อกับระบบผลิตวิดีโอ (ดู srs.md หัวข้อ 1.2 และภาคผนวก 4.4)

## 2. ผู้เกี่ยวข้องและบทบาท

| ผู้เกี่ยวข้อง | บทบาท | หน้าที่ |
|---|---|---|
| เจ้าของโปรเจกต์ | ผู้ตัดสินใจและผู้ตรวจรับ | กำหนดลำดับบท ตอบประเด็นเปิด ตรวจรับรายบทจากหน้าจอจริง |
| Claude | ผู้ออกแบบ ผู้พัฒนา ผู้ทดสอบ | เขียนเอกสาร ออกแบบ เขียนโค้ด ทดสอบ รายงานผลตามจริง |
| นักเรียน | ผู้ใช้ปลายทาง | ใช้แบบจำลองเพื่อเรียนรู้ ไม่มีส่วนในการพัฒนา |
| ผู้สอน | ผู้ใช้ร่วม | ใช้ประกอบการสอนและส่งลิงก์กรณีตัวอย่างให้นักเรียน |

หลักการทำงาน: Claude ทำทุกขั้นเอง เจ้าของโปรเจกต์สั่งและตรวจ ไม่มีขั้นตอนที่ต้องรอคนอื่นเขียนหรือรัน

## 3. วงจรพัฒนาที่ใช้

ใช้ SDLC แบบวนรอบทีละบท (iterative) หลังจากวางโครงสร้างพื้นฐานเสร็จ แต่ละรอบทำครบทุกขั้นสำหรับบทนั้น

```mermaid
flowchart LR
    A["วางโครงสร้างพื้นฐาน<br>ไลบรารี แม่แบบ แคตตาล็อก"] --> B
    subgraph รอบต่อบท
        B["ทบทวนการ์ดออกแบบ<br>ของบทนั้น"] --> C["เขียนโค้ดแบบจำลอง<br>ทุกชุดในบท"]
        C --> D["ทดสอบอัตโนมัติ<br>และทดสอบบนมือถือ"]
        D --> E["เจ้าของตรวจรับ<br>จากหน้าจอจริง"]
        E -->|แก้ไข| C
    end
    E -->|ผ่าน| F["บันทึก changelog<br>ปรับสถานะ ready"]
    F --> B
```

เหตุผลที่ไม่ออกแบบหน้าจอเต็มทั้ง 76 ชุดก่อนเขียนโค้ด: ทุกชุดใช้โครงหน้าจอเดียวกันที่ออกแบบและตรวจแล้ว ส่วนที่ต่างกันระบุไว้ในการ์ดครบ หน้าจอจริงจึงเกิดจากโค้ดโดยตรงและตรวจจากของที่เล่นได้ ประหยัดการทำซ้ำ

## 6. เกณฑ์ความสำเร็จของโครงการ

1. แบบจำลองครบ 76 ชุด ครอบคลุม 195 เรื่อง ทุกชุดสถานะ `ready`
2. ทุกชุดผ่านชุดทดสอบอัตโนมัติ และผ่านการตรวจรับรายบทจากเจ้าของโปรเจกต์บนมือถือ
3. นักเรียนที่ไม่เคยใช้เปิดแล้วปรับค่าเห็นผลได้ภายใน 30 วินาที
4. ทั้งโฟลเดอร์ `lab/` คัดลอกไปที่ใดก็เปิดใช้ได้โดยไม่ต้องต่ออินเทอร์เน็ต

## 7. การสื่อสารและการตรวจรับ

- Claude รายงานทุกครั้งที่บทหนึ่งพร้อมตรวจ พร้อมผลทดสอบตามจริง และระบุสิ่งที่ยังไม่ได้ทำถ้ามี
- เจ้าของโปรเจกต์ตรวจจากหน้าจอจริง (เปิดไฟล์หรือลิงก์) ไม่ต้องอ่านโค้ด
- ข้อแก้ไขบันทึกเป็นรายการในรอบนั้น แก้เสร็จแล้วรายงานซ้ำ
- การเปลี่ยนขอบเขตให้แก้ srs.md ก่อนเสมอ
